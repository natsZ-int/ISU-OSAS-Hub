A service type with existing requests is deactivated rather than deleted, so historical requests keep a readable service name.

Design intent

Maintain the OSAS service catalogue: what students can request, the instructions they see, and the attachments each service demands.

What this screen establishes

  1. Each type has a name, description, instructions, active flag, display order and a set of requirements.
  2. Only active types appear in the student catalogue, ordered by display order.
  3. The instructions field is shown verbatim to students, so it is written for them.
  4. Requirement count is shown per type so the attachment burden is visible.

Structural source: WF-A-18 in the wireframe set. The mockup restates the same information architecture in the institutional palette, so a change to one is a change to both.
