ISU OSAS Hub interface language

A single visual and interaction vocabulary for the 46 high-fidelity screens in this deliverable. Every token is taken from the stylesheet the application actually loads (public/css/app.css), so the mockups and the delivered system describe the same interface. Where a value is not present in the application it is marked as proposed and never used as though it were implemented.

1. Colour

Institutional green carries structure and primary action; university gold is reserved for emphasis and never for status. Status never relies on colour alone: every badge also carries a word.

3. Space, radius and elevation

A 4 px base unit governs padding and gaps. Radii are 6 px for controls, 10 px for inputs and notices, 14 px for cards and panels. Only two shadows are used: a hairline for resting cards and a larger one for overlays and device frames.

4. Buttons

A screen has exactly one primary action. Secondary actions are outlined; navigational actions are ghost. Destructive actions are visually distinct and never adjacent to the primary action without a confirmation step.

SizesOne primary action per screen; destructive actions sit away from the primary path.

5. Form controls

Labels sit above controls and are never used as placeholders. Required fields carry an asterisk; help text explains consequences; errors appear under the field and repeat at the top of the form after a failed submit.

13. Content rules

Wording is the interface. These rules keep the screens speaking with one voice.

Do

“Two required documents have no verified upload.”

“The deadline must be on or after the start date.”

“Requests in this state are waiting on the student.”

Do not

“Oops! Something went wrong.”

“Invalid input.”

“Please kindly be informed that…”

Sentence case for everything except badges and table headers. Dates are written 15 Nov 2026; identifiers keep their generated form SCH-2026-000184; money uses two decimals and a thousands separator PHP 148,000.00; percentages use one decimal 6.5%. Status words are never abbreviated.

14. Governance

The tokens are not aspirational. They are read from the application stylesheet, and this page is generated from the same source as the mockups.

Token group Defined inChange process
Colour, radius, spacing, typepublic/css/app.css Change the application first, then regenerate this page; the mockups follow.
Component markupdocumentation/_tools/wf_kit.py One renderer serves both wireframes and mockups, so a change is made once.
Mockup stylingUI-UX-Mockups/assets/mockup.css Values are copied from the application stylesheet; no new colour is introduced.
Status vocabulary_spec/requirements.csv A new stored status must also reach the state machine, the badge map and the traceability matrix.
No Figma file accompanies this deliverable. The design system is implemented as HTML and CSS so that it can be inspected in a browser, diffed in version control, and rendered into the document without a second source of truth.
